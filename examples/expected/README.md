# Worked example: sample input and expected output

This directory is the "comprehensive test run" required for a CPC Computer
Programs in Physics submission. It lets a reviewer or Technical Editor run the
program and compare the result against a known-good output without any external
data.

## 1. Input

| File | Role |
| --- | --- |
| `data/scores.csv` | Score stream. **One numeric column, no header** (a header is a hard input error because `load_scores` rejects non-numeric rows). 16,000 rows, deterministic, regenerated by `examples/make_sample_scores.py` with seed 20260912. |
| `../configs/worked_example.json` | Deployment specification: 10-bit unsigned score with 8 fractional bits, `nearest_even` rounding, `error` saturation; 0.01 confidence, 12 Hz budget, prescale 4, 0.05 Hz rate LSB, 32-bit counter. |
| `../configs/worked_example_narrow_counter.json` | Identical, except the rate counter is 4 bits, to exercise the counter-range predicate. |

The score LSB is `2^-8 = 0.00390625`, so integer code `q` corresponds to score
`q/256`. All three cases below use threshold code 250 or 249, i.e. scores
0.976563 and 0.972656.

## 2. The three cases

Run from the repository root with `PYTHONPATH=src`.

### Case 1 — CERTIFIED

```powershell
py -m ratecert --config configs/worked_example.json --scores examples/data/scores.csv `
    --exposure-s 20 --threshold-code 250 --output examples/expected/case1_certified.json
```

Expected: `CERTIFIED`, and the certificate must contain

| Field | Value |
| --- | --- |
| `threshold_code` | 250 |
| `count` | 145 |
| `point_rate_hz` | 7.25 |
| `upper_rate_hz` | 8.778530889551678 |
| `quantization_margin_hz` | 0.025 |
| `deployment_margin_hz` | 3.1964691104483216 |
| `recorded_point_rate_hz` | 1.8125 (raw/4) |
| `saturation_count` | 0 |

The whole point of the example is the pass predicate. The point estimate is
7.25 Hz, but certification does **not** use it. The decision is

    8.778530889551678  (exact one-sided Poisson upper rate, alpha = 0.01, T = 20 s)
  + 0.025              (nearest-even 0.05 Hz register margin, delta_r/2)
  = 8.80353            <= 12.0  budget     -> CERTIFIED, margin 3.1964691104483216 Hz

### Case 2 — refused on the budget margin

```powershell
py -m ratecert --config configs/worked_example.json --scores examples/data/scores.csv `
    --exposure-s 20 --threshold-code 249 --output examples/expected/case2_budget_refusal.json
```

Expected: `NOT_CERTIFIED` with exactly one reason,

    finite-sample upper rate plus fixed-point margin exceeds budget

Here `count` = 205, `upper_rate_hz` = 12.04261, so
`12.04261 + 0.025 = 12.06761 > 12.0`. The refusal is by **0.068 Hz**. This case
exists to show that the tool refuses marginal configurations rather than
relaxing its confidence requirement, and that the refusal is retained as a
valid, machine-readable object.

### Case 3 — refused on the counter range, with two independent reasons

```powershell
py -m ratecert --config configs/worked_example_narrow_counter.json --scores examples/data/scores.csv `
    --exposure-s 20 --threshold-code 250 --output examples/expected/case3_counter_refusal.json
```

Expected: `NOT_CERTIFIED` with **two** reasons,

    rate counter overflow: count 145 exceeds 15
    finite-sample upper rate exceeds the declared rate-counter full scale

A 4-bit counter at a 0.05 Hz LSB has full scale `(2^4 - 1) x 0.05 = 0.75 Hz`,
which cannot hold either the observed count or the upper rate. The two
predicates are reported separately because they call for different remedies:
one is a range problem, the other a count-overflow problem.

## 3. What a reviewer should conclude

- The same command path serves all three outcomes; there is no separate
  "failure mode" code path.
- Only the first two predicates (statistical bound and register margin) enter
  the pass condition.
- Refusals are structured data with reasons, not exceptions or silent zeros.
- The raw rate and the prescaled recorded rate are both reported and are never
  conflated: prescale 4 reduces the recorded rate to a quarter of the raw rate
  and does **not** reduce the raw background rate that the budget constrains.
